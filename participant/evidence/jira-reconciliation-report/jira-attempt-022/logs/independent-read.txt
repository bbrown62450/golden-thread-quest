READER 1: THE ADVERSARIAL READ
  It reproduced what follows by running the copy, except where marked "reasoned".

  HIGH
  1. An item was called synchronized when Jira's status or type differed. Names were compared after they were
     cleaned, and cleaning turns every mark into a question mark and cuts at 40 characters. A copy holding
     `QA?Review` against a Jira answering `QA/Review`, with the same last-changed time: synchronized. An admin
     renaming a status does not change an item's last-changed time, so this can happen. The report did not say so.
     CHANGED: a copy can carry, for each item, a short checksum of its type and status names as Jira wrote them, and
     the tool compares that with the same checksum of what Jira answers. A difference the cleaned names do not show
     makes the item stale or conflicted, and the reason says so. The fixture's copy carries the checksums.
     NOT CHANGED, AND NOW SAID: a copy with no checksums is still compared by cleaned names. The copy adopted from
     the saved-query result is one, because that result holds cleaned names only. Section 6 of the report says how
     many items that applies to: for the real run, all 25.
     ALSO CHANGED: `adopt` refused a whole result if any status held a mark. It now cleans the name and says how
     many it cleaned.

  MEDIUM
  2. The tool's own check agreed with itself. The numbers of the items "in Jira only" were taken from the tool's own
     entries, not from Jira's list. With two of three such entries dropped it printed "CHECK: 2 = 2. PASSED". With

     CHANGED: the check is given the numbers Jira's list returned, straight from the list. It also holds the rule
     for each state a second time, as a table, and compares every item's state with what was found for that item.

     not Jira's answers.
  3. The mark "(incomplete)" on a trend row sat in a tenth cell under nine headings, which a rendered table drops.
     On an incomplete run the table still printed "not yet copied 0".
     CHANGED: the trend has a "Complete" column. On an incomplete run "not yet copied" reads NOT KNOWN in the table,
     the trend and the output, the total says "(the local copy only)", and section 1 cites the log line.
  4. The copy's file name reached the report as it was. A file name holding a line break and a heading forged a
     heading in the report.                              CHANGED: letters, digits, dot, dash and underscore only.
     The same input under another file name rewrites the report.   NOT CHANGED: the name is in the report.
  5. --log wrote over a person's file that began "Project: ...", and made folders.

     after it, or as its own refusal. No folder is made.    NOT CHANGED: the write of the log is not atomic.
  6. A write failing part way left files of two runs side by side, with nothing in the files to say so.
