READER 1: TRYING TO BREAK THE TOOL
  It reproduced most of what follows by running the copy.

  HIGH
  1. The notes file can be overwritten through --log and through `rules --write`.
       --log naming the notes in other capitals: on this kind of disk that is the same file. The sync finished, said
       the notes were UNCHANGED, and then saved its log over them.
       --log naming a second name (a hard link) of the notes: the same.
       `rules --write` naming the notes: no check at all.
       The same trick in capitals overwrote the copy.
     CHANGED: the tool asks the disk whether two paths are one file. It refuses a place named like a notes file, a
     link, or a file with a second name, for any file of its own. `rules --write` refuses a file that is not a rules
     document. The notes' checksum is taken again after the log is written. Tests and planted bugs for each.

  MEDIUM
  2. A comment that is still there is marked "not returned" when the list shifts between pages: one comment deleted
     and one added while the pages are read. Every count agrees.
     CHANGED: a comment missing from the list is asked for by its own identifier. Jira answering 200 refuses the sync;
     only 404 marks the comment; anything else refuses. This is a fourth kind of request, still a GET.
  3. History rules match on the field's display name. A custom field named "Status" holding "Waiting on" and a
     person's name was kept as a status change. Keys were picked out of any sentence.
     CHANGED: a field Jira marks custom is never material. A key is kept only when Jira gives exactly a key.
     NOT CHANGED: the name of an unlisted field is printed, cleaned. It is in the limitations.
  4. The line "Already edited when first copied" showed the comment's latest edit time.
     CHANGED: it keeps the time it describes. A change with the same words now leaves a note on the page as well.
  5. Some content of a comment is lost without a word: a date, a status badge, an emoji, a card.
     CHANGED: a badge and an emoji keep their words. The rest is kept by kind, and the page says the comment is not
     whole and what is missing.

  LOW
  6. An "edit" was noted when the visible words had not changed.   CHANGED: it is noted as a change of another kind.
  7. One comment the tool cannot read stopped every sync.           CHANGED: it is kept, flagged. Half a character
     in a comment is replaced.
  8. Lines inside a comment's fence could start like a heading, a mark or a table row of the page.
     CHANGED: every line of a comment is set in by four spaces. A limit remains and is stated.
  9. Reasoned, not run: no lock against two syncs at once; the unsalted site fingerprint; a temporary file left by a
     killed sync; "To Do -> To Do" in the real run.
     CHANGED: a same-name change says so. The rest are NOT CHANGED and are in the limitations.

  WHAT IT LOOKED FOR AND DID NOT FIND
    A way to add a comment or a change twice. A silent removal. A missed edit where the body differs. A write when
    nothing changed. A way to the notes through --name, --out-dir or a link on the two written files. A request
    other than the reads. A bad answer that did not refuse. A credential or the site's address in the output.
  WHAT IT SAID IT COULD NOT VERIFY
    Whether a real Jira's count of comments includes comments hidden from the account. Nor can I. It is a limitation.
