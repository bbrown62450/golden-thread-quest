READER 2 was given the tool, its tests, the commit hook, the recording script and the three records. It was asked to

WHAT READER 2 FOUND, AND WHAT WAS DONE

 1. SERIOUS. A credential typed on the command line was printed back. The tool had no option that takes a
    credential, so `call --token VALUE` was refused. But the refusal was Python's ordinary one, which repeats what
    it did not understand, value included. No mask could catch it: the tool had never been told that value.
    AND THE RECORD HID IT. The recording script changed that one line of the saved output, replacing the fake value
    with the words "<the fake token>", so the record looked clean. That was my doing and it was wrong: a record
    that is edited to look right is not a record.
    DONE: the tool now never repeats a command line it does not understand. The line in the script that edited the
    record is deleted. The record now checks, on the output exactly as printed, that the value is absent, with the
    variable set and not set. Three planted bugs cover it.
 2. The mask worked only when the file was run as a script. Used from another program, a failure went out unmasked.
    DONE: the tool's main function reports its own failures through the mask. One test and one planted bug.
 3. The value was written down for masking only after the command line was read.
    DONE: it is the first thing done.
 4. The mask can give a value away by what is missing, if the value is a piece of ordinary text.
    DONE IN PART: a value shorter than 20 characters is refused and never masked. The rest is stated as a limit.
 5. The commit hook did not look at renamed files.            DONE, and shown in logs/pre-commit.txt part 5.
 6. The hook could take a file name beginning with a dash for an option, and cut a name at a space.
                                                              DONE, and shown in part 6.
 7. The hook scanned the file on disk, not the staged copy that would be committed.
                                                              DONE, and shown in part 4.
 8. The hook said "blocked: a credential was found" when the scan had not run at all.
                                                              DONE: a different message. Shown in part 7.
 9. "The whole repository" was narrower than it sounded: new files were scanned only under participant/, and the
    record did not name them.
    DONE: every file Git does not track or ignore, in the whole repository, listed by name. What is still not
    scanned is said in the record: ignored files, history, other branches, commit messages, pictures.
10. The second pattern was never run over the repository, and its misses and false alarms were not shown.
    DONE: it is run over every tracked file. It reports one place, in the program's own tests of its scanner, which
    is a made-up value and not a credential. That false alarm is left in the record as it is. Its misses (capitals,
    name on another line, key cut in two) and a second false alarm (a checksum) are shown in logs/leak-scan.txt 4c.
11. The records were checked before their last lines were written, not as saved.
    DONE: logs/records-scan.txt reads the three finished files back and scans them.
12. The command lines in the record showed `NAME=<value> command`, the very form the policy forbids.
    DONE: the record now says the variable is set in the environment of the process, which is what happens.
