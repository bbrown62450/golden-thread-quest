READER 1: TRYING TO BREAK THE TOOL
  It said it found no blocking fault, two high, the rest medium or low. It reproduced most by running the copy.

  HIGH
  1. A saved filter can leave the project. My check for paired quotes did not know that JQL reads a backslash before a
     quote as part of the text. A filter with \" in it was accepted and closed the bracket early.
     CHANGED: a backslash in a filter is refused. The tool's description no longer says "cannot". A test and a
     planted bug cover it.
  2. COMPLETE with the wrong set, when changes cancel out: one item leaves the query during the run and another joins.
     NOT FIXED. I do not think it can be, from outside Jira. CHANGED: the output says so under every complete
     result, and so do the tool's description, SKILL.md and PROOF.md.

  MEDIUM
  3. --log and --out naming the same file: the log was written over the result.
     CHANGED: refused before Jira is asked, and the log is not written.
  4. The search for credentials came after the result file was written.
     CHANGED: the search is made before the write, over the output so far and the result.
  5. Wrong numbers when a page fails in its middle: that page's items were counted as arrived.
     CHANGED: a page is judged whole before any of it is counted.
  6. Values saved as blanks or question marks under COMPLETE, with no warning.
     CHANGED: an item without its type, status or time fails the run. Letters and digits of any script are kept. The
     output says how many names were changed by cleaning.

  LOW
  7. A moved count was also called a shortfall.                         CHANGED.
  8. Two items with one key and different ids were both saved.          CHANGED: keys are compared as well as ids.
  9. Two inputs made the tool crash with a traceback.                   CHANGED: both are handled, and anything
     unforeseen is an incomplete run with no result.
  10. `isLast` as the text "false" was taken for the end.               CHANGED: it must be true, or absent.
  11. A file name or a setting's name was printed as it came.           CHANGED: unseen characters are replaced.
  12. My reading of the configuration differed from YAML in five places, and refused some valid YAML.
      CHANGED where the two would read a file differently: `parameters` twice, a leading zero, no space after a
      colon, and words YAML reads as true, false or nothing are refused. NOT CHANGED: valid YAML that is refused
      stays refused (a `---`, a comment after a value). The file's header now says how to write it.
  13. A base address in capitals was refused with a misleading message. CHANGED: it is the same site.
  14. The site fingerprint is an unsalted hash.                         NOT CHANGED. Earlier quests use the same
      one. It is in the limitations.

  WHAT IT LOOKED FOR AND DID NOT FIND
    The token, email, encoded form or site address in the output, the log or the result. Text from Jira in the output.
    Any request beyond the two reads. A way to change the query through --set, --project or --query. A status or
    body oddity that did not fail closed. A temporary file left behind.
